06 / Investigation

It was not a page-rendering defect.

The browser could load Strapi admin, yet the ecommerce plugin’s server endpoint did not exist in the generated test application.

Root cause
Generated-app plugin composition was incomplete.
Evidence chain

The 404 identified a missing server plugin—not a broken Tax Rules component.

The diagnosis followed the request path from a visible admin shell to an unavailable plugin API route, then back to the generated app template that determines installed and enabled server plugins.

OBSERVED

Admin shell loaded.

Strapi booted and served `/admin`, proving the E2E application and browser session were functional.

OBSERVED

Tax Rules data request returned 404.

`GET /ecommerce-base/tax-rules?page=1&pageSize=10` had no matching server route.

VERIFIED

Generated app neither installed nor enabled the plugin.

`tests/app-template/config/plugins.js` was empty and the template dependency list omitted `@strapi/ecommerce-base`.

Admin bundle registration

`packages/core/strapi/src/admin.ts` makes the UI plugin available to the core admin bundle.

Generated-app server loading

The E2E application still needs the package dependency and explicit plugin enablement to register routes, models, and lifecycle hooks.
