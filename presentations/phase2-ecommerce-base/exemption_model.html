04 / Rules engine

Dynamic exemption model

Exemptions are persisted policy data, matched against checkout context at tax-computation time.

A matching exemption reduces gross tax. The selected rule is traceable alongside currency, rate, and applied tax rules in the stored order.
Contextual, time-bound, auditable

Only eligible rules compete; the highest matching percentage wins.

The new collection type supports broad regional relief, customer-specific policies, and code-gated campaigns without hard-coding jurisdictional logic into checkout.

Scope
Active status, region, and currency gate every rule before customer-level conditions are evaluated.
Customer fit
Customer relation, customer tags, and email domains optionally narrow eligibility to the intended population.
Commercial fit
Minimum subtotal, exemption code, start date, end date, and percentage express campaign and statutory requirements.
Selection sequence

Five deterministic checks

Reject inactive, region-mismatched, or currency-mismatched rules.
Validate identity, tag, and email-domain conditions when configured.
Apply subtotal and start/end-date limits.
Require a caller-supplied code when the rule defines one.
Sort valid matches by percentage and use the highest.
